**栈（stack）**

用于实现函数调用。由编译器自动分配释放，存放函数的参数值和局部变量

<img src=".\assets\v2-3cf83ebfecd29f8dcc5ed62db2002d52_1440w.jpg" alt="img" style="zoom:32%;" />

**堆（heap）**

用于存放动态分配的变量。由程序员使用**new/delete、malloc/free**动态分配和释放

**全局区/静态区/数据段**

存放全局变量和静态变量，程序结束时释放

* .data（data segment）：存放初始化了的全局变量和静态变量
* .bss（bss segment）：存放未初始化的全局变量和静态变量，实际上不占用磁盘空间

**常量区**

存放常量字符串，程序结束后由系统释放

**代码区（text segment）**

存放程序执行代码，在程序运行前已确定，并通常属于只读

# 内存管理

## 内存分配

主要考虑程序的**动态内存分配**部分

### malloc/free new/delete

malloc/free：分配/释放一块连续的内存

new/delete：封装malloc/free；在申请自定义类型的空间时，new会调用构造函数，delete会调用析构函数，而malloc与 free不会

用户态的内存分配/释放**接口**，在底层使用 `brk`（用于中小分配）和 `mmap`（用于大块分配）向操作系统申请内存

### brk/mmap

brk：扩展 heap 的上界（通过移动堆的末尾指针），用于处理较小的内存请求

mmap：不在堆上操作，向内核申请一块独立的、不与堆相连的内存区域，用于处理较大的内存请求

|  **对比项**  |      **匿名映射**      |     **文件映射**     |
| :----------: | :--------------------: | :------------------: |
| **数据来源** |        内核分配        |       磁盘文件       |
|  **持久化**  |     进程退出后消失     |    可持久化到文件    |
| **适用场景** | 动态内存分配、进程共享 | 文件 I/O、内存数据库 |
|  **初始化**  |        默认清零        |      从文件加载      |

### 虚拟地址空间

[Linux用户虚拟地址和内核虚拟地址的关系 - L](http://liujunming.top/2017/07/02/Linux用户虚拟地址和内核虚拟地址的关系/)

|   **地址类型**   |              **描述**              |      映射方法      | **典型范围 (x86_64)** |
| :--------------: | :--------------------------------: | :----------------: | :-------------------: |
| **用户虚拟地址** |    用户态进程独享，每个进程独立    |      四级页表      |         0G~3G         |
| **内核虚拟地址** | 内核态共享，所有进程和内核自身共用 | （大部分）线性映射 |         3G~4G         |

内核虚拟地址：只有一份，所以提前固定下来一片连续的物理地址空间，按线性方法来映射，以提高转换效率

用户虚拟地址：不同进程的虚拟地址空间和页表是独立的（可能不同进程的同一个虚拟地址通过各自的页表映射到不同的物理地址），随着进程的创建销毁不断分配释放内存

### 物理内存

<img src=".\assets\v2-2aad0eadc7245264ae6f83b8ca11b34a_1440w.jpg" alt="img" style="zoom:50%;" />

CPU被划分为多个节点(node)，内存则被分簇(bank)，一个CPU-node对应一个内存簇bank，即每个内存簇被认为是一个node（内核中表示为`pg_data_t`的实例）

每个物理内存节点node被划分为多个内存管理区域zone（一个zone通过`struct zone_struct`描述）
