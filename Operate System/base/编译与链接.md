## 编译

### 预处理

- 删除所有的注释信息
- 删除所有 #define 并展开所有宏定义
- 插入所有 #include 文件的内容到源文件中的对应位置，include 过程是递归执行的

```sh
gcc -E hello.c -o hello.i
```

### 编译

对预处理之后的文件进行词法分析、语法分析、语义分析并优化后生成相应的汇编文件

```sh
gcc -S hello.i -o hello.s
```

### 汇编

将汇编代码转化为机器指令

```sh
gcc -c hello.s -o hello.o
```

## 链接

### 静态链接

* **地址与空间分配**

  * 合并相似的节

    相似权限的节会被合并成段

    <img src=".\assets\elf-similar-merge.png" alt="img" style="zoom:20%;" />

  * 合并符号表：链接器读取每个目标文件的符号表，将它们合并成一个**全局符号表**，其包含了所有输入文件中定义和引用的所有符号（全局函数和全局变量）

* 符号解析和重定位

  重定位表（目标文件中**`.rel`**开头的段）：

  ```sh
  $ objdump -r a.o
  
  a.o:     file format elf64-x86-64
  
  RELOCATION RECORDS FOR [.text]:
  OFFSET           TYPE              VALUE
  0000000000000023 R_X86_64_32       share
  0000000000000030 R_X86_64_PC32     swap-0x0000000000000004
  0000000000000049 R_X86_64_PC32     __stack_chk_fail-0x0000000000000004
  
  
  RELOCATION RECORDS FOR [.eh_frame]:
  OFFSET           TYPE              VALUE
  0000000000000020 R_X86_64_PC32     .text
  ```

  符号表（**.symtab**）：

  ```sh
  $ readelf -s ab
  ...
  10: 0000000000000000     0 FILE    LOCAL  DEFAULT  ABS a.c
  11: 0000000000000000     0 FILE    LOCAL  DEFAULT  ABS b.c
  12: 0000000000400114    45 FUNC    GLOBAL DEFAULT    1 swap
  13: 00000000006001a0     4 OBJECT  GLOBAL DEFAULT    3 shared
  14: 00000000006001a4     0 NOTYPE  GLOBAL DEFAULT    3 __bss_start
  15: 00000000004000e8    44 FUNC    GLOBAL DEFAULT    1 main
  16: 00000000006001a4     0 NOTYPE  GLOBAL DEFAULT    3 _edata
  17: 00000000006001a8     0 NOTYPE  GLOBAL DEFAULT    3 _end
  ```

  * 链接器为合并后的每个节分配最终的运行时内存地址，并更新全局符号表中所有符号的地址
  * 链接器遍历每个输入文件的重定位表，
  * 对于重定位表中的每一个条目，链接器会：
    - 找到该条目指向的、需要被修改的代码位置。
    - 从全局符号表中查出该条目引用的符号的最终地址。
    - 将这个最终地址写入到代码位置，替换掉原来的占位符

### 动态链接

一个`.so`共享库可以同时被多个进程使用

* 编译时，链接器对程序中对`.so`库函数的调用，生成一个指向 **PLT (过程链接表)** 的调用指令

* 程序加载时，动态加载器在标准路径（如 `/lib`, `/usr/lib`）查找 `.so` 文件，将其代码段 (`.text`) 和数据段 (`.data`)**映射**到该进程的虚拟地址空间中

  * 对于变量：动态加载器计算出所有变量的最终虚拟地址，用这些地址去**回填每个进程私有的 GOT 表**

    * **GOT表**：

      多个进程共享一个库时，有一些不一致的数据（映射该共享库的虚拟基地址、全局变量、静态变量）

      只有一个共享库，不能通过修改共享库的方式满足所有进程的需求

      使用GOT表：GOT存储在各个进程的`.data`段，当某进程需要引用某个全局变量时，可以通过其私有的GOT中指向的项间接引用

* 对于函数（延迟绑定，在程序加载时并不解析函数的地址，而是等该函数被第一次调用时再解析，以加快程序启动速度）：

  第一次调用时：PLT → GOT  → 动态加载器 → 回填GOT
